# Nextish Todo API

A runnable API example with users, their projects, and project todos. It demonstrates CRUD routes, nested parameters, `(workspace)` route groups, inherited middleware, per-method Zod validation, typed parsed inputs, and OpenAPI generation.

This is a local learning example. Data lives in memory and resets whenever the process restarts, including development restarts. There is no authentication: anyone who can reach the server can modify the demo data. The server binds to `127.0.0.1`; use invented user information. The nested URL checks enforce user/project/todo relationships, not caller identity.

Use Node.js **22.13.0 or newer**. From the repository root:

```sh
pnpm install --frozen-lockfile
npm run todo:dev
```

Open `http://127.0.0.1:3001`. Users are at `/api/users`, and the OpenAPI 3.1 document is at `/openapi.json`. Set the `PORT` environment variable to change the port. Stop with Ctrl+C.

To run compiled JavaScript:

```sh
npm run build
npm run todo:start
```

The production start script sets `NODE_ENV=production`. It still uses the same in-memory demo store and localhost binding. Development uses Node's process watcher; the Nextish router uses its default `watch: false`, so edits restart the whole example and reseed the data. SIGINT, SIGTERM, and listen failures close the HTTP server and router.

The example uses the repository's existing dependencies. Its imports point to the local `src` implementation, as in the smaller blog example. When copying it into another application, replace imports ending in this repository's `src` with `nextish-express-router`, and `src/zod` with `nextish-express-router/zod`; install Express, Zod 4, and the package as described in the [main README](../../README.md).

The route structure is:

```text
example/todo/
├── app.ts
├── server.ts
├── store.ts
├── schemas.ts
└── api/
    └── (workspace)/
        ├── middleware.ts
        └── users/
            ├── route.ts
            └── [userId]/
                ├── route.ts
                └── projects/
                    ├── route.ts
                    └── [projectId]/
                        ├── route.ts
                        └── todos/
                            ├── route.ts
                            └── [todoId]/
                                └── route.ts
```

`(workspace)` is omitted from URLs. Its middleware sets `Cache-Control: no-store` for every loaded users, projects, and todos handler. The app mounts the router at `/api`; `path.join(__dirname, "api")` locates routes beside either the TypeScript source or compiled app, independently of the working directory.

Each application instance gets a separate `TodoStore` in `app.locals`. Routes call its scoped operations through `getStore(req)`. Every operation checks parent relationships before reading or changing records. Deleting a project also deletes its todos; deleting a user deletes that user's projects and todos. Other users and projects remain intact. Replace this store with database operations and add authentication before adapting the example for real users.

The API accepts and returns JSON. Collection GETs return arrays; individual GETs, POSTs, and PATCHes return a resource object.

| Methods | Path | Purpose |
| --- | --- | --- |
| GET, POST | `/api/users` | List or create users |
| GET, PATCH, DELETE | `/api/users/:userId` | Read, update, or delete a user |
| GET, POST | `/api/users/:userId/projects` | List or create that user's projects |
| GET, PATCH, DELETE | `/api/users/:userId/projects/:projectId` | Read, rename, or delete a project |
| GET, POST | `/api/users/:userId/projects/:projectId/todos` | List or create project todos |
| GET, PATCH, DELETE | `/api/users/:userId/projects/:projectId/todos/:todoId` | Read, rename, complete, reopen, or delete a todo |

Create users with `{ "name": "Grace", "email": "grace@example.test" }`, projects with `{ "name": "Work" }`, and todos with `{ "title": "Write tests" }`. Names, titles, and emails are trimmed; emails are normalized to lowercase and must be unique. Names allow up to 100 characters, titles up to 200, and emails up to 254. IDs are generated by the server and are opaque strings. New todos have `completed: false`.

PATCH accepts at least one editable field: `name` or `email` for users, `name` for projects, and `title` or a boolean `completed` for todos. Omitted fields keep their current values. Unknown fields, including attempts to change IDs or parent IDs, are rejected. GET on a todo collection optionally accepts `?completed=true` or `?completed=false`; other values and repeated values are rejected.

POST returns **201** and a `Location` header. Successful reads and updates return **200**, and DELETE returns **204** with no body. Validation failures return **400** with Zod's `{ error, issues }`; malformed JSON returns **400**, oversized request bodies **413**, unknown resources or mismatched parents **404**, and duplicate emails **409**. Unexpected failures return a generic **500** without exposing stack traces. Collections are intentionally small and unpaginated in this demo.

Every startup seeds these records:

| Resource | ID | Contents |
| --- | --- | --- |
| User | `demo-user` | Ada, `ada@example.test` |
| Project | `demo-project` | Learn Nextish, owned by `demo-user` |
| Todo | `demo-todo` | Try the todo API, incomplete, in `demo-project` |

Try a workflow against the seeded project:

```sh
curl http://127.0.0.1:3001/api/users

curl http://127.0.0.1:3001/api/users/demo-user/projects

curl -i -X POST http://127.0.0.1:3001/api/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"Grace","email":"grace@example.test"}'

curl -i -X POST http://127.0.0.1:3001/api/users/demo-user/projects \
  -H 'Content-Type: application/json' \
  -d '{"name":"Work"}'

curl -i -X POST http://127.0.0.1:3001/api/users/demo-user/projects/demo-project/todos \
  -H 'Content-Type: application/json' \
  -d '{"title":"Write the README"}'

curl -X PATCH http://127.0.0.1:3001/api/users/demo-user/projects/demo-project/todos/demo-todo \
  -H 'Content-Type: application/json' \
  -d '{"completed":true}'

curl 'http://127.0.0.1:3001/api/users/demo-user/projects/demo-project/todos?completed=false'

curl -i -X DELETE http://127.0.0.1:3001/api/users/demo-user/projects/demo-project/todos/demo-todo

curl http://127.0.0.1:3001/openapi.json
```

Use each POST response's `Location` URL to read or update the newly created resource. Restart the example to restore the seeded records.

Run all repository checks with `npm run lint` and `npm test`. To focus on this example after building, run `node --test test/todo.test.cjs`.
